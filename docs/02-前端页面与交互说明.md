# 02. 前端页面与交互说明

## 2.1 前端方案总览

本项目的前端方案由 SimpleCMS-Framework 与 Laravel 12 共同承载，借助 Inertia + Vue 3 构建企业展示层与后台交互层：

- SimpleCMS-Framework 提供统一的模块化数据和后台能力约束
- Laravel 12 提供服务端路由、控制器和页面数据返回
- Inertia 负责前后端无缝协作，把页面数据直接渲染到 Vue 组件
- Vue 3 负责页面结构和交互逻辑
- CSS 使用 SCSS，适合页面样式复用

从产品视角看，这一套方案是 SimpleCMS IP 中“内容 + 展示 + 管理”一体化交互层的实现方式。

核心入口：

- [resources/js/app.js](../resources/js/app.js)
- [resources/views/Pages](../resources/views/Pages)
- [app/Http/Controllers/Frontend/HomeController.php](../app/Http/Controllers/Frontend/HomeController.php)

## 2.2 页面组织方式

当前前端页面位于：

- [resources/views/Pages/Frontend](../resources/views/Pages/Frontend)

已实现页面包括：

## 2.4 组件数据流

以首页为例：

- 控制器在 [app/Http/Controllers/Frontend/HomeController.php](../app/Http/Controllers/Frontend/HomeController.php) 中返回数据
- 这些数据包括 company、stats、services、cases、process 等
- Vue 页面通过 defineProps 接收对象字段
- 页面使用 v-for、v-if 等指令完成列表渲染和布局

这种流转方式很适合中小型 CMS 和企业官网场景，因为：

- 数据结构清晰
- 组件低耦合
- 修改页面内容变得简单

- 主色调：蓝色科技风

- 设计原则：简洁、专业、可信

适合：

- 数字化企业官网
- 服务商展示页
- SaaS 公司主页
- 创新型企业品牌页

## 2.6 主要交互点

目前页面的交互主要集中在：

- 导航跳转
- 区块式信息展示
- 列表渲染
- CTA 按钮动作
- 需求咨询入口

后续可以继续扩展：

- 表单提交
- 搜索和筛选
- 详情页跳转
- 企业资讯检索
- 站内多语言切换

## 2.7 需要注意事项

- Vue 模板中的字符串值要避免直接写纯符号表达式，例如 ¥ 或 100%
- 组件样式应保持一致，避免不同页面视觉风格断裂
- 业务数据尽量放在控制器中，而不是硬编码到页面中
- 页面层要保持结构清晰，便于后续 SEO、静态化或服务端渲染扩展

## English / 英文

### 2.1 Frontend Architecture Overview

This frontend is built through the combined strengths of SimpleCMS-Framework and Laravel 12, using Inertia + Vue 3 to create both the enterprise presentation layer and the backend interaction layer.

- SimpleCMS-Framework provides modular data definition and backend capability constraints
- Laravel 12 provides server-side routing, controllers, and page data responses
- Inertia keeps the frontend and backend tightly connected by rendering page data directly into Vue components
- Vue 3 handles page structure and interaction logic
- SCSS is used for reusable and maintainable page styling

From a product perspective, this architecture is the interaction layer of the SimpleCMS IP for content + display + management integration.

Main entry points:

- [resources/js/app.js](../resources/js/app.js)
- [resources/views/Pages](../resources/views/Pages)
- [app/Http/Controllers/Frontend/HomeController.php](../app/Http/Controllers/Frontend/HomeController.php)

### 2.4 Component Data Flow

Taking the home page as an example:

- the controller in [app/Http/Controllers/Frontend/HomeController.php](../app/Http/Controllers/Frontend/HomeController.php) returns structured data
- the data includes company, stats, services, cases, and process information
- the Vue page uses defineProps to receive the data object
- the page uses v-for and v-if to render lists and layouts

This flow is well suited for small to medium CMS and enterprise-site scenarios because:

- data structure is clear
- components are loosely coupled
- modifying page content is straightforward

- Avoid writing plain symbol expressions directly in Vue templates, such as ¥ or 100%
- Keep component styling consistent to avoid visual discontinuity across pages
- Place business data in controllers rather than hardcoding it in the page
- Keep page structure clear to enable future SEO, static generation, or SSR expansion
