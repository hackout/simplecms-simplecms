# 03. 后端架构与模块说明

## 3.1 后端入口

后端入口在 SimpleCMS 的能力架构中，处于“框架能力 + 业务实现”的桥接层：

- SimpleCMS-Framework 提供通用服务、权限、模型和接口抽象
- Laravel 12 负责应用主框架和路由编排
- 具体业务模块在项目中按功能拆分实现

入口分为两类：

- 前台展示路由：位于 [routes/web.php](../routes/web.php)
- API / 认证接口：位于 [routes/api.php](../routes/api.php)

当前前台路由已覆盖：

- `/` 首页
- `/about` 关于页
- `/services` 服务页
- `/solutions` 方案页
- `/products` 产品页
- `/cases` 案例页
- `/news` 新闻页
- `/contact` 联系页

后台管理入口位于：

- `/backend`

## 3.2 控制器结构

前台控制器位于：

- [app/Http/Controllers/Frontend](../app/Http/Controllers/Frontend)

主要包括：

- HomeController：企业官网入口与页面数据提供
- AuthController：前台认证相关逻辑
- PublicController：公共初始化接口
- UserController / UserGroupController：用户相关控制器
- ProfileController：个人资料控制器

后台控制器位于：

- [app/Http/Controllers/Backend](../app/Http/Controllers/Backend)

主要模块包括：

- AccountController
- UserController
- UserGroupController
- DictController
- DictItemController
- MenuController
- RoleController
- ManagerController
- ManagerLogController
- SystemController
- BackendController

## 3.3 模块职责

### 用户管理

用于维护后台用户与前端用户的账户信息、权限和状态。

### 角色与权限

通过角色控制不同页面和接口的访问权限，属于标准 RBAC 设计思路。

### 菜单管理

用于管理管理后台菜单树结构，支持动态菜单渲染。

### 字典管理

用于统一管理系统中的状态、类别、标签等枚举数据。

### 日志管理

用于记录关键操作和后台行为，便于审计和追踪。

## 3.4 模型层

模型位于：

- [app/Models](../app/Models)

常见模型：

- Account.php
- Manager.php
- User.php
- UserGroup.php
- Profile.php

这些模型通常用于：

- 用户和权限映射
- 账号状态管理
- 用户资料与角色关系
- 分组管理

## 3.5 中间件与认证

项目已经接入 Laravel 的认证体系以及 Sanctum 的登录方式：

- `auth` 中间件用于后台认证
- `guest` 中间件用于游客访问控制
- `role` 中间件用于访问控制

这部分使系统适合：

- 企业管理后台
- 用户数据隔离
- 角色权限控制
- 接口安全访问

## 3.6 路由设计思路

当前路由结构简明清晰：

- 前端展示路由直接注册到 [routes/web.php](../routes/web.php)
- 后台功能采用按模块分组的风格
- 权限校验直接绑定到具体 route 规则中

这样做的优点是：

- 维护成本低
- 安全控制集中
- 功能扩展简单

## 3.7 数据库设计思路

数据库目录：

- [database/migrations](../database/migrations)
- [database/seeders](../database/seeders)

项目结构中已经具备：

- 用户表
- 管理员表
- 数据字典表
- 角色/菜单等核心表
- 缓存和任务表

升级扩展时建议：

- 按业务模块拆表
- 用字典表统一枚举值
- 用中间表处理用户/角色/分组关系

## 3.8 后端扩展方式

常见扩展步骤：

1. 创建新的 Controller
2. 在 routes 中注册路由
3. 在数据库中建立表或迁移
4. 添加对应 Model
5. 绑定权限和菜单入口
6. 在前端页面调用接口或 Inertia 渲染

## 3.9 当前后端特点

- 结构清晰，适合继续扩展
- 模块化管理强，适合企业级治理
- 权限中心化设计较完整
- 可迅速做成内部管理平台或 CMS 模板
- 适合从 demo 阶段推进到真实业务系统

## English / 英文

### 3.1 Backend Entry

In the SimpleCMS architecture, the backend sits between framework capabilities and business implementation:

- SimpleCMS-Framework provides general services, permissions, models, and interface abstractions
- Laravel 12 provides the main application framework and route orchestration
- concrete business modules are implemented by feature according to project structure

The entry points are divided into two categories:

- frontend display routes in [routes/web.php](../routes/web.php)
- API/auth interfaces in [routes/api.php](../routes/api.php)

The current frontend routes cover:

- `/` home
- `/about` about page
- `/services` services page
- `/solutions` solutions page
- `/products` products page
- `/cases` cases page
- `/news` news page
- `/contact` contact page

The backend management entry is located at:

- `/backend`

### 3.2 Controller Structure

Frontend controllers are located in:

- [app/Http/Controllers/Frontend](../app/Http/Controllers/Frontend)

Main modules include:

- HomeController: enterprise site entry and page data provider
- AuthController: frontend authentication logic
- PublicController: public initialization interface
- UserController / UserGroupController: user-related controllers
- ProfileController: personal profile controller

Backend controllers are located in:

- [app/Http/Controllers/Backend](../app/Http/Controllers/Backend)

Main modules include:

- AccountController
- UserController
- UserGroupController
- DictController
- DictItemController
- MenuController
- RoleController
- ManagerController
- ManagerLogController
- SystemController
- BackendController

### 3.3 Module Responsibilities

#### User management

Used to maintain backend user and frontend account data, permissions, and status.

#### Roles and permissions

Controls access to different pages and interfaces through a role-based model, following standard RBAC patterns.

#### Menu management

Used to manage the backend menu tree and render dynamic menus.

#### Dictionary management

Used to unify system states, categories, and enumerated values.

#### Log management

Used to record critical operations and backend behaviors for audit and traceability.

### 3.4 Model Layer

Models are under:

- [app/Models](../app/Models)

Common models include:

- Account.php
- Manager.php
- User.php
- UserGroup.php
- Profile.php

These models are typically used for:

- user and permission mapping
- account status management
- user profile and role relationships
- grouping management

### 3.5 Middleware and Authentication

The project is integrated with Laravel’s authentication system and Sanctum login approach:

- `auth` middleware for backend authentication
- `guest` middleware for guest access control
- `role` middleware for route-level access control

This makes the system suitable for:

- enterprise management backend
- user data isolation
- role-based permission control
- secure interface access

### 3.6 Routing Design

The current route structure is straightforward:

- frontend presentation routes are registered in [routes/web.php](../routes/web.php)
- backend features are grouped by module
- permission checks are bound directly to route rules

Benefits:

- low maintenance cost
- centralized security control
- simple feature expansion

### 3.7 Database Design

Database directories:

- [database/migrations](../database/migrations)
- [database/seeders](../database/seeders)

The project already includes:

- user tables
- administrator tables
- dictionary tables
- role/menu core tables
- cache and job tables

When expanding, it is recommended to:

- split tables by business module
- unify enumerations with dictionary tables
- use pivot tables for user/role/group relationships

### 3.8 Backend Extension Method

Typical extension steps:

1. Create a new controller
2. Register the route in the routing file
3. Create database tables or migrations
4. Add the corresponding model
5. Bind permissions and menu entries
6. Call the API or render Inertia pages from the frontend

### 3.9 Current Backend Characteristics

- clear structure and easy to extend
- strong modular management suitable for enterprise governance
- centralized permission design is relatively complete
- can quickly become an internal management platform or CMS template
- suitable for moving from demo stage to a real business system
